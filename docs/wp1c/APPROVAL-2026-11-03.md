# Owner approval — WP1C offline-only (2026-11-03)

## Decision and source

The owner explicitly approved the **offline-only WP1C** development package in [Issue #11](https://github.com/dragonidf/ha-heating-2/issues/11), and instructed updating all relevant Codex rules in this repository.

**G0 APPROVED; WP0 REVIEWED; WP1A ACCEPTED (PR #6); WP1B ACCEPTED (PR #9, main `1d3a9204a449bff14b7f0c8f2a8c8f33e71e6016`); G1 BLOCKED (B01–B08 remain open, Issue #3); WP1C APPROVED OFFLINE ONLY.**

This approval is limited to writing and testing isolated predictive thermal-model/observer, bounded planning, challenger-learning qualification, and pure fireplace/night-air fan-demand policies and their synthetic evidence. It does **not** approve any real Home Assistant integration, installation, actuation, production changes, legacy modifications, private data import or rollout. WP2A and later are **not approved** by this decision.

## Authorized scope

1. Implement the bounded, deterministic WP1C module groups defined in Issue #11: `packages/thermal/`, `packages/planner/`, `packages/learning/` if necessary, and `packages/fan_policy/`.
2. Preserve existing WP1A+WP1B software and all 155 known tests; build new synthetic scenario/property/failure/unit tests and reproducible CI on 3.12/3.13/3.14.
3. Reference the old `dragonidf/ha-heating-ai` repository **read-only** for the historical thermal model and equations; record source commit and exact baseline provenance. Never mutate it, and never guess or publish user-specific current coefficients/configuration.
4. Keep software side-effect-free where specified; compute returns a **proposal**, never sends any thermostat/fan command. Reuse existing types and strict negative guards; do not insert a live transport.
5. Develop in separate `feature/wp1c-offline-model-planner` branch and leave a code PR unmerged for independent review; include full technical report, parity limits, 86/38 traceability, test commands, and final-SHA CI evidence.
6. Fix all ordinary defects within scope before handing off the PR; concise final report (PR URL, commit SHA, test count, remaining blockers).

## Hard constraints

- **Production Home Assistant is untouched**: no configuration, entities, helpers, automation, database, dashboard, app/add-on, AppDaemon, network, Zigbee2MQTT, Sky Radar, Deye, HACS, reload, restart, backup, import or commands.
- No physical thermostat, fan, inverter, power or heating commands or tests. No live Home Assistant integration, enabled gateway, scheduler or persistent background process in WP1C.
- Legacy repo `dragonidf/ha-heating-ai` is read-only, never edited.
- No private user state, live source readings, passwords, house locations, IPs, real entity IDs, secrets, logs or backups in code, CI, PR, GitHub issues, reports or public fixtures. Use only artificial data.
- No physical auto-selection/switching of 3/6/9 kW stages: these remain candidate planning scenarios only.
- Do not invent a global 180-minute session limit or change legacy one-shot semantics. B08 is open.
- Unverified source/meter topology, thermal coefficients, physical characteristics, accuracy and N100 performance must remain `BLOCKED`, `NOT_PARITY_VERIFIED` or `NOT_TESTED`, never quietly pass.
- No new code package automatically starts after WP1C. Do not merge code PR automatically.
- This is a later **phase-specific** authorization, overriding only older “WP1B only/no WP1C” phase labels in historic work documents. All ADR01–07, owner addenda and G1–G9 gates remain in force.
