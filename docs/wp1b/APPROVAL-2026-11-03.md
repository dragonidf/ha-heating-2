# Owner approval — WP1B (2026-11-03)

## Decision

Owner explicitly approved starting **WP1B strictly in an isolated development/testing environment**, under [Issue #7](https://github.com/dragonidf/ha-heating-2/issues/7), and requested moving efficiently along the already approved roadmap toward the replacement controller.

**G0: APPROVED. WP0: reviewed. WP1A: merged (PR #6). G1: BLOCKED (B01–B08 remain open in Issue #3). WP1B: AUTHORIZED OFFLINE ONLY. WP1C and later: NOT AUTHORIZED by this decision.**

The authorization **does not** waive G1–G9 acceptance gates, permit installation into Home Assistant, allow any actuation, or warrant a claim of physical or production safety.

## Approved actions

- Write and test **offline-only** transactional control-state persistence, simulated command gateway, deterministic fault/crash/restart/replay harness, and supporting tests/docs in `dragonidf/ha-heating-2`.
- Use entirely artificial settings, timestamps, owners, readings, plans, and fixture/device names; isolate database files and processes to a disposable local sandbox.
- Work with a dedicated code branch and PR, inspect its CI, and stop for review. Original WP1A pure contracts/kernel must remain I/O-free; any changes must preserve their contract and regressions.
- Model the next stages in docs and collect **read-only** baseline evidence separately, where expressly available, without treating missing evidence as complete.

## Absolute restrictions

- **No changes in production Home Assistant**: configuration, entities, automations, helper states, dashboards, Recorder, files, add-ons, HACS, SQLite, OS, or network.
- No thermostat/fan/Deye/Tuya/MQTT/HA commands; no physical tests, automation trigger, reload, restart, update, deployment, enabled integration, sidecar or background daemon.
- `dragonidf/ha-heating-ai` remains read-only and unchanged. No new production backups; no collection, publication or upload of private runtime dumps, passwords, coordinates, logs or household data.
- No live Home Assistant adapter or command sender. The simulated gateway may **only** call a fake actuator implementation that has no imports/routes to real equipment.
- No WP1C, release or cutover without a separate approval. Do not merge the eventual WP1B code PR automatically.
- Public repository: use only synthetic data and sanitized status/evidence.

## Precedence

This later approval supersedes the outdated phase prohibition in `docs/wp1a/WP1A-TASK.md` **only for the narrow offline WP1B scope**. ADR01–07 and owner clarifications remain unchanged. B01–B08 and G1 remain BLOCKED. See `WP1B-TASK.md` and root `AGENTS.md` for binding execution rules.
