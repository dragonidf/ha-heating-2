## Closed transport and reuse

`ThermostatExecutor` is inert by default. Even when explicitly enabled, it accepts only the exact `IsolatedClimateMock` type; arbitrary/real transports are rejected. `physical_commands_enabled=False` is unconditional. There is no HA service/HTTP/MQTT/Tuya sender, package activation hook or real principal in this change. No production connection, controller disable, deployment or physical equipment test occurred. Native sandbox boundaries remain intact.

The mock reuses the existing WP1B `FakeActuator` reservation/generation fence and issuer-sealed observations. Test credentials are in-process mock capabilities, **not HA authentication evidence**. The same actuator rejects overlapping controller/watchdog/updater writers. A transactional holder in the native existing critical store prevents another executor instance from claiming the same native controller. Mapping, capabilities and independently qualified thermostat temperature are unknown by default; test fixtures must explicitly supply them. Modes other than known manual HEAT cannot activate a ceiling-constrained writer; vendor AUTO remains unqualified and cannot bypass it.

The existing NativeBackend final HEAT limiter remains the only setpoint algorithm. Its issued proposal is internally copied so caller mutation cannot authorize a different setpoint. Revalidation uses the recorded planner/one-shot request, the actual current effective upper/owner/STOP/voltage/KWS/room/persistence guards, and separately fresh thermostat-local data. It runs before claiming, immediately before mock dispatch, throughout the wait and before accepting readback. It never refreshes local temperature provenance from command/readback timing. No UI/model/planner algorithm was rewritten.

## Delivery and durable uncertainty

The existing disposable `NativeStore` critical SQLite hosts one additive versioned executor record: writer holder, pending identity, immutable command facts/stages, uncertainty latch and one-shot claims. Commands have a canonical boot/owner/proposal identity. A PREPARED record is committed and independently read back before send; replay returns the stored outcome instead of sending again. Only one pending command is allowed. One-shot ticket claims precede dispatch and cannot be reused with a new owner epoch. Native restart also retains the existing armed→unknown-outcome behavior. No receipt or one-shot state is upgraded to physical success by send alone.

Service return changes only the stage to SENT. The mock's send method does **not** generate any device report. Independently injected readback must provide the exact command identity, issuer/boot/epoch, observed manual HEAT mode and snapped target, timestamp strictly after the command and within freshness/deadline, known writer set and independently qualified device evidence. HA-state-write origin, stale/wrong/late/unqualified/contradictory echo or external manual override cannot ACK. A successful simulation is labelled `echoed_mock`; **physical_ack=False and contacts_open=null always**, including after successful readback. The native UI's existing physical flags remain false.

Delay/drop/no-op/timeout, failed durability, restart or lease loss produces UNCERTAIN/blocked delivery. No positive retry occurs. The uncertainty latch does not automatically clear on a late report or simulated withdrawal echo; a commissioned reconciliation/re-activation procedure is still required before real operation. A queued mock generation is invalidated on preemption. When current exclusive authenticated mock ownership, fresh manual-HEAT temperature, supported dynamic ceiling and durable safety state still qualify, one bounded negative withdrawal attempt uses the same existing limiter/withdrawal code. This STOP/preemption-only path has fixed `heat_permitted=False`; it cannot resume, arm or permit ON. Independent readback reporting manual override, unknown writers or non-HEAT/AUTO mode revokes the local credential before any recovery attempt. Its regression first reproduced an inappropriate withdrawal and then passed with no command to the external owner. If ownership/authentication is lost or AUTO/thermostat/persistence is unknown, it does not fight another writer or claim physical OFF. KWS/OEM hardware protections remain independent.

Database work is dispatched off the event loop; an in-flight async send/readback does not lock out memory-first STOP. Commands remain fenced during asynchronous durability work. Ledger corruption/storage failure is fail-closed, not a reason to reset or replay.
