# Owner approval — WP2B isolated offline UI (2026-11-04)

## Decision and limits

The owner explicitly approved **WP2B development and automated testing in an isolated synthetic/offline environment only**, under [Issue #17](https://github.com/dragonidf/ha-heating-2/issues/17), and asked for matching GitHub/Codex rules.

**G0 APPROVED; WP0 REVIEWED; WP1A ACCEPTED (PR #6); WP1B ACCEPTED (PR #9); WP1C ACCEPTED (PR #13); WP2A ACCEPTED (PR #16, main `6ba17e078863280c481c165be57035ac6d01165a`); WP2B APPROVED OFFLINE ONLY; G1/B01–B08 BLOCKED (Issue #3).**

This is phase-specific permission for **frontend code, offline synthetic demo, mock API fixtures and browser/unit/accessibility tests**. It does **not** approve WP2C or any live HA adapter, HA connection, production UI/dashboard edits, equipment actions, private data export/import, native HA installation, deployment, shadow, physical testing, or cutover.

## Permitted implementation

- One cohesive fully functional UI package defined in [Issue #17](https://github.com/dragonidf/ha-heating-2/issues/17): `Дім · Історія · Налаштування`, nested model/diagnostics, responsive charts, advanced controls behind progressive disclosure, synthetic simulation-only interactions.
- Use approved [UI design](../spec/heating-ai-2.0/05-UI-design.md), versioned accepted WP2A read/status/history/settings envelopes, simulated subscriptions and CAS saves. Explicitly distinguish real evidence, synthetic fixtures, controller requests, fake ACK and **unverified actual device behavior**.
- Original 12h-before forecast must require **both source issue time and trusted archival receipt by cutoff**, be immutable and honestly MISSING when absent. Actual measurements keep gaps; energy quality/coverage/unknown cannot become zero or savings.
- Provide a **locally browsable** demo using *only* synthetic fixtures and no live HA URL/token/session, direct HA call, MQTT, real device interface, public serving, CDN, analytics or mandatory internet.
- Full source, tests, screenshots using only synthetic data, docs/ADR, 86/38 requirement/scenario traceability, quality/coverage evidence, optional benchmark measured **only** on the development test host.
- Preserve **all 351 previously accepted Python tests**, add real JS/TS/component/browser tests and accessible, responsive layouts; keep all Python 3.12/3.13/3.14 CI and strict type checks. Do not silently lower thresholds.
- Work in `feature/wp2b-offline-frontend`, produce **one open/unmerged implementation PR** for independent QA, then stop. Do not auto-merge or start WP2C.

## Mandatory prohibitions

- **Do not read, contact, install to, or modify production Home Assistant**: entities, helpers, services, dashboards, scripts, automations, AppDaemon, HACS, Zigbee2MQTT, Sky Radar, Deye, Recorder, network, device, host or backups. No real HA compatibility testing in this approval.
- Never change `dragonidf/ha-heating-ai`: legacy reference is read-only. Do not upload any user/private config, state, telemetry, home locations/addresses, real entity IDs, LAN addresses, screenshots with household data, tokens, secrets or backups to the public repository.
- **No real actuator transport**, HA native enabled component, physical thermostat/fan/boiler/3/6/9 stage control, real command sender, second writer or actual shadow agent. An offline simulation controls only mock state, must be clearly labeled.
- Maintain WP1A STOP/manual/one-writer/unknown-vs-zero guards and all existing E/P/F/M invariants. Client controls cannot bypass a backend authorization gate; fake receipt cannot become a physical success indicator. Failure/offline must disable privileged interactions.
- G1/B01–B08 and gates G2–G9 **remain BLOCKED/NOT_TESTED**. No assertion of real household accuracy, electrical topology, OEM safety, target SQLite durability, authenticated HA WebSocket compatibility, 7-day/3-cycle shadow or live performance.
- B08 180-minute question remains unresolved. Do not turn a one-shot into a global scheduled heating cap.
