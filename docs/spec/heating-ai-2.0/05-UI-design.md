# Heating AI 2.0 — дизайн інтерфейсу

**Статус:** дизайн-специфікація й статичний концепт. Реальний новий застосунок не реалізований. Чинний live UI у браузері не перевірявся; аналіз зроблено за кодом, попередніми аудитами й вимогами власника. Усі числа на `ui-concept.svg` — демонстраційні, не поточні виміри.

## Продуктова ідея

Перший екран відповідає на три питання: чи комфортно, що робить система, що буде далі. Одна головна температура, одне зрозуміле рішення, один плановий період. Технічні докази доступні в деталях. Облік завжди має видимі scope/quality, без складних назв алгоритмів на щоденному екрані.

Постійна навігація: **Дім · Історія · Налаштування**. На desktop — верхній компактний bar; на телефоні — нижня nav з трьома пунктами. «Модель і діагностика» відкривається зі сторінки налаштувань або посилання «Точність прогнозу» в історії. AI не окрема незрозуміла центральна вкладка: власнику потрібні прогноз/факт і якість; AI advice — додатковий expandable блок у деталях моделі.

## Екран «Дім»

Порядок зверху вниз:

1. Назва будинку/опалення, статус зв'язку й доступна кнопка паузи. Якщо offline — час останніх даних, без удаваних live станів.
2. Comfort hero: кімната, ціль зі степпером ±0,5 °C, day/sleep label. За age warning — «Вимір 35 хв тому»; при недовірених даних велике «—», останнє значення в поясненні.
3. Рядок actual action: «Котел гріє · ≈6,3 кВт» або «Котел не гріє · наступний сеанс 05:30». Desired/control status окремим коротким рядком тільки коли відрізняється: «Автоматика призупинена; котел працює самостійно».
4. Один priority notice: safety → втрата керування → дані → комфорт → економіка. Інші події — counter/details; не кілька однакових жовтих коробок.
5. Температурний прогноз 24 год: factual до now, current prediction після now, comfort band, heat/outage/fire tracks. Під графіком компактний план із 2–3 наступними сеансами й поясненням ранку.
6. «Цикл до 07:00, 04 листопада»: початковий план / відомий факт / поточне очікування, coverage. Деталі розкривають prestart, unknown minutes і причини overrun. Немає порівняння rolling 24h з нічним циклом.
7. Камін/циркуляція як компактна спільна картка; speed control у sheet. Рекуператор/витяжка — у read-only details теплових факторів.

При 390×844 перший viewport містить hero, actual action, priority notice (за наявності) й початок chart. Нормальний default екран ≤1 300 px без expanded details; це проєктна ціль, перевіряється із довгими українськими текстами.

## Екран «Історія»

За замовчуванням календарний тиждень; presets 24 год / 7 днів / 30 днів і custom dates у Києві. Один графік з легендою:

| Серія | Вигляд | Семантика |
|---|---|---|
| Фактична температура | Суцільна світла/темна контрастна | Реальні звіти; gap не з'єднується |
| Завчасний прогноз | Фіолетова штрихова | Незмінний original forecast, виданий ≥12h до reference; lead у tooltip |
| Поточний прогноз | Блакитна пунктирна, тільки future overlay за запитом | Новий план, не підміна завчасного |
| Комфортний діапазон | Тиха напівпрозора смуга | Зміни day/sleep й історичної settings revision |

Actual-only працює без жодного forecast. «На цей період немає завчасного прогнозу» — змістовний empty state, не нескінченний spinner. На штриховій кривій доступний issued time/plan provenance; технічний hash не зачитується звичайному користувачу. Hover/touch/arrow keys дають одне спільне tooltip за часом; таблиця еквівалентних значень доступна без кольору й precision pointer.

Під графіком: «24h перевірки: 3 дні, недостатньо доказів» або calibrated metrics by horizon. «Модель готова до керування» й «Доведена точність 24 год» мають різні labels. Energy chart/report вибирається окремим metric switch, з одиницями й quality categories; °C і кВт·год не на одній оманливій осі.

## Налаштування

Основний рівень: день/сон, preferred heat hours, стратегія, циркуляція, місячний budget і operational mode. У кожному полі коротке пояснення наслідку. Expert рівень: sensors/topology, physical mode/calibration, learning, freshness, model coefficients, diagnostics, updates. Advanced sections collapsed, пошук по назві параметра. Не дублювати десятки helpers як різні knobs одного значення.

Температурна ціль — швидкий immediate intent із receipt. Складні зміни — staged form із «Зберегти» та «Скасувати». Saved тільки після persisted revision; failed save залишає змінені поля й помилку, не false toast «Успішно». Конкурентне збереження показує «Налаштування змінилися в іншому вікні» й diff, без silent last-write-wins. Undo повертає draft, повторний Save явний.

Фізичний профіль: «На котлі встановлено: 9 кВт» + пояснення «Це опис для прогнозу. Перемикач ТЕНів на котлі не змінюється». Якщо рекомендація 6→9 — потрібна фізична дія/перевірка, не зелена кнопка «увімкнути 9 кВт» без реального actuator capability.

One-shot: вибір конкретної дії з назвою, умовою наступного живлення, строком дії й «Скасувати запит». Не неоднозначний switch «Відновити один раз». Вимкнений/прострочений/виконаний/невідомий результат показуються різними станами.

## Візуальна система

Обрана концепція — темний графіт із теплим світлим текстом, cool lavender/teal для прогнозу, стриманий теплий акцент для тепла. Не брати палітру Nova зі стороннього завдання без її reference: у цьому завданні такого image brief немає. Зберегти вимогу власника червоного нагріву/горіння, жовтих переходів, але не робити нормальний нагрів схожим на критичну аварію: червоний локальний icon/track, danger — окремий значок і текст.

| Token | Dark | Light | Застосування |
|---|---|---|---|
| canvas | #111318 | #F5F6F8 | Фон |
| surface | #1B1E26 | #FFFFFF | Карти, чітко відділені від canvas |
| surface-raised | #252A35 | #ECEFF4 | Controls/sheets |
| text | #F2F0EC | #20232B | Основний |
| muted | #ADB5C4 | #525E70 | Пояснення, перевірити contrast |
| border | #394150 | #CDD3DD | Межа, не єдина ознака state |
| prediction | #B8AAFF | #6650BA | Очікувана температура |
| control | #8EDBD0 | #176F67 | Дії/selection |
| heating | #FF8E8E | #AE333F | Факт нагріву/полум'я |
| warning | #F4C872 | #8B5B0A | Перехід/невизначеність |

Tokens мають семантичні CSS names і адаптуються до HA theme локально в Shadow DOM; global theme не редагувати. Остаточний contrast всіх пар перевірити в браузері, а не вважати автоматично достатнім за цим переліком. Шрифт — HA system font stack, без обов'язкових зовнішніх font assets; цифри tabular. Hero 52/56 mobile, 64/68 desktop; section 18/24; body 15/22; helper 13/18; touch control 44–48 px. Grid 4/8 px; cards radius 20, controls 12, pill тільки для короткого статусу. Розмежування площин — border і різниця luminance, без суцільної «сірої каші» або зайвих тіней.

Desktop ≥1100: максимум content width 1200, grid 7:5 — forecast/plan ліворуч, cycle/fire/context праворуч; hero на всю ширину. Tablet 700–1099: дві колонки, chart full width. Mobile <700: одна колонка; жодних fixed-height текстових tiles. Text wrap, min-width:0, довгі назви не обрізають критичні числа. 200% text перетворює split blocks у stack.

## Поведінка й мікротексти

| Ситуація | Текст на екрані |
|---|---|
| Нормальний простій | «Тепла достатньо. Наступний нагрів о 05:30» |
| План рахується, чинний діє | «Оновлюємо план. Поточний розклад діє до 06:00» |
| Немає grid | «Електрики немає. Котел очікує відновлення» |
| Майбутнє невідоме | «Графік на завтра ще не підтверджено. План умовний» |
| Факт неповний | «Враховано 8,2 кВт·год. У вимірах є прогалини: 18 хв» |
| Plan overrun | «Очікуємо на 2,1 кВт·год більше: будинок охолов сильніше» — лише якщо є це evidence; інакше «Причину перевищення не встановлено» |
| Дефіцит | «За планом температура може впасти до 20,7 °C о 18:30» + horizon/uncertainty |
| Ручне втручання | «Автоматика на паузі після зміни термостата» + «Продовжити» |
| Немає history | «За ці дати немає збережених вимірів» |
| Збій команди | «Термостат не підтвердив команду. Працює резервний режим» — лише якщо fallback справді підтверджено; інакше «Керування не підтверджене» |

Жодних «останній локальний факт», «beam expanded», «validated=true» на щоденному екрані. Reason code лишається в diagnostics. При стані unknown замість 0 показувати «—» з поясненням. Колір завжди доповнюється текстом/icon/лінійним патерном. Motion ≤120 мс для press/state, без пульсації; reduced-motion вимикає transitions.

Приймання: U01–U10 у requirements.csv, browser matrix і практичні задачі документа 04. Статичний SVG дозволяє погодити напрям, але не підміняє клікабельний prototype і accessibility QA після дозволу розробки.
